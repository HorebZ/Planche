# Planche

Native macOS client for GitHub Projects v2. Tauri 2 shell, React webview, all logic in Rust.

## Layout

- `crates/planche-core` owns the domain, the GitHub GraphQL client, the SQLite cache, and the sync engine. It has no Tauri dependency.
- `crates/planche-cli` and `app/src-tauri` are thin shells over `planche-core`. Neither contains GitHub or cache logic.
- `app/src` is the React frontend. It reaches the system only through `app/src/ipc/bindings.types.ts`.
- `app/src/styles/tokens.css` is the source of truth for theme values; `app/src/assets/brand/` holds the app icons and README logos.
- The roadmap lives in GitHub issues, starting at #1. Each phase issue lists its files, steps, tests, and live scenarios.

## Commands

- `bun install` at the root installs the root tools and `app/` (a Bun workspace).
- `bun run check` runs fmt, clippy, Rust tests, Biome, the `app/` checks (`tsc`, Biome, the design check, Vitest), and GraphQL validation. It must pass before every push.
- `cargo test -p planche-core` runs the core tests.
- `cargo run -p planche-cli -- board @me/<number>` prints a board.
- `bun run dev` at the root loads the ignored root `.env` and runs the app. In dev, `http://localhost:1420/playground` shows every UI component in every state.
- `cd app && bun run test:e2e` runs the focused WebKit e2e suite. Run `bunx playwright install webkit` once first. `test:visual`, `test:perf` and `test:video` run the optional browser checks and captures.
- Live tests run against the real tracking project "Planche" (`@me/2`). A scenario that changes a card restores it at the end.

## Rules

- Every network call, keychain access, file access, and SQLite query lives in `planche-core`. The webview never calls `fetch`. Do not add `tauri-plugin-http`, `tauri-plugin-sql`, or `tauri-plugin-fs`.
- `app/src/ipc/bindings.types.ts` is generated by tauri-specta. Never edit it. `bun run check` fails when it is stale.
- GraphQL documents live in `crates/planche-core/graphql/*.graphql`. Validate every change with `bun run validate:gql`. Measure `rateLimit.cost` before adding a query to the sync loop. Refresh the schema with `bun run update:schema`.
- `github/wire.rs` types are private. `github/ops.rs` converts them to `domain.rs` types. Nothing outside `github/` sees a wire type.
- Only the sync engine writes `item`, `item_field_value`, `item_assignee`, and `item_label`. User actions become an `Intent` row in `pending_mutation`. Never write optimistic state into server tables.
- A new user action is a new `Intent` variant with `apply`, `to_operations`, and test cases. Move-like intents also get cases in `fixtures/move_cases.json`, which both Rust and TypeScript replay.
- Server data lives in TanStack Query only. Zustand holds UI state only, such as selection and open dialogs. Never copy query data into Zustand.
- Keyboard shortcuts are declared only in `app/src/keyboard/shortcuts.ts`.
- CSS targets WebKit, meaning WKWebView on macOS 15 and later. Check layout changes in the Playwright `webkit` project. Do not use Chromium-only features.
- GitHub sign-in uses OAuth Device Flow with `repo`, `read:org`, and `project`; a classic PAT remains supported. A fine-grained PAT is bound to one resource owner, so it cannot cover the viewer and several organizations at once.
- Never log the token. `PLANCHE_TOKEN` overrides the private local session for dev and tests. Never expose it through a `VITE_` variable. Session storage stays in `planche-core`, with directory mode `0700`, file mode `0600`, and atomic writes; no Keychain access is needed.
- Tauri stays on 2.x. Do not upgrade to the 3.0 alphas.
- Write a comment only for a non-obvious why.
- Prefer unit and integration tests for behavior. Keep tests beside the implementation: `Name.test.ts(x)` for Vitest, `module.test.rs` or `module.integration.test.rs` for Rust, loaded with `#[cfg(test)]`. Reserve colocated `Name.e2e.ts` tests for critical browser interactions; rendering checks use `Name.visual.e2e.ts`. Repeat themes only for rendering checks. The production TypeScript config excludes test files; never import tests or `test-support` from application code.
- Place reusable fixtures and fake services in `_fixtures/` beside the file that declares their types. Frontend domain types are generated from Rust into `app/src/ipc/bindings.types.ts`, so their fixtures live in `app/src/ipc/_fixtures/`. Name fixture code `<name>.fixtures.ts`, including mocks such as `backend.fixtures.ts`; Rust uses `<name>.fixtures.rs` inside its `_fixtures/` directories. TypeScript factories deep-clone the result and replace top-level fields with `Partial<T>` overrides; use a separate factory for each card variant. Do not add tests for the generic fixture factory. Rust uses ordinary factory functions and struct update syntax, with fixture modules gated by `#[cfg(test)]`; do not add a production `Default` solely for tests. Keep scenario-specific data in its test and the cross-language contract in `fixtures/move_cases.json`. `_fixtures/` is excluded from the production TypeScript roots and Tailwind scan; the browser mock backend is imported only behind the dev/mock-build guard.
- Use a role suffix for TypeScript files when it clarifies their purpose, such as `.types.ts`, `.models.ts`, `.service.ts`, `.routes.ts` or `.fixtures.ts`. Keep names concise and avoid redundant suffixes when the role is already explicit.
- Group code by logical step, with a blank line between validation, preparation, side effects, and the result. In tests, separate setup, action, and assertions; keep related declarations and assertions together. Prefer descriptive names over single-letter locals outside short closures. Preserve this spacing when adding or editing code: Biome and rustfmt keep logical blank lines but do not insert them. `bun run format` fixes formatting; `bun run check` verifies it.

## Design

- UI is built only from the tokens in `app/src/styles/tokens.css` and the components in `app/src/components/ui/`.
- Never improvise a color. No hex, `rgb()`, `oklch()`, or Tailwind palette class such as `bg-gray-100` outside `tokens.css`. GitHub label and option colors are data and may be applied inline. `bun run --cwd app check:design` enforces this.
- Never use `dark:` utilities. Each color token is a `light-dark()` value, so `prefers-color-scheme` drives the theme. A `.light` or `.dark` class forces a theme on any subtree, including `<html>`.
- Radix portals must render into `usePortalContainer()` so overlays inherit the theme of the subtree that opened them.
- A new component or a new state goes into `app/src/components/ui/` and `/playground` first, in light and dark, then into a feature. Force states in the playground with `data-preview="hover|focus|active"`.
- Icons come from `lucide-react`. The mockups use Material Symbols. Pick the closest lucide equivalent.
- Motion durations come from the tokens. `--pl-dur-fast` (150 ms) covers hover, focus, and press. `--pl-dur-base` (180 ms) covers menus, popovers, and tooltips. `--pl-dur-slow` (200 ms) covers panels, dialogs, and the card drop. Easing is `--pl-ease`. `prefers-reduced-motion` sets every duration to 0.
